## Część 2 — macierz przeglądarek (Firefox + WebKit/Safari)

Suita E2E jedzie tylko Chromium; ten przebieg to automatyczny odpowiednik „1 przejścia" na Firefox + Safari. Spec: `apps/admin/e2e/golive-2126-browser-matrix.spec.ts`, config `apps/admin/playwright.browser-matrix.config.ts` (osobny, poza domyślną bramką CI). 6 krytycznych widoków: dashboard, produkty, modelowanie, importy, feedy, ustawienia/użytkownicy.

### Uruchomienie

```bash
cd apps/admin && pnpm exec playwright install firefox webkit
# Firefox (natywnie rozwiązuje pim.localhost) — pełna bramka console-clean:
E2E_BASE_URL=https://pim.localhost pnpm exec playwright test --config=playwright.browser-matrix.config.ts --project=firefox
# WebKit (nie rozwiązuje pim.localhost — patrz niżej) — przez host localhost, render-only:
E2E_BASE_URL=https://localhost pnpm exec playwright test --config=playwright.browser-matrix.config.ts --project=webkit
```

### Wyniki

| Silnik | Widoki | Bramka | Wynik |
|---|---|---|---|
| **Firefox** | 6/6 | render + **console-clean** | ✅ zielone |
| **WebKit (Safari)** | 6/6 | render-only (patrz uwaga) | ✅ zielone |

**Firefox:** wszystkie 6 widoków renderują się i mają czystą konsolę. Jeden przejściowy fail złapał **realną różnicę silnika**: Firefox loguje nieudane pobrania fontów woff2 z Vite `@fs` jako błędy JS (Chromium ignoruje) — artefakt **dev-servera** (prod bunduje fonty inaczej), odfiltrowany jako benign.

**WebKit:** nie rozwiązuje `pim.localhost` bez wpisu `/etc/hosts` (ten sam gotcha co cold-start L11 / [#2182](../../../issues/2182); dodanie wpisu wymaga sudo — niedostępne autonomicznie). Obejście: host `https://localhost` (Caddy ma go w TRUSTED_HOSTS, cert obejmuje). Pod tym obejściem widoki **renderują się poprawnie** (asercje tekstu + zrzuty), ale konsola ma szum **wyłącznie dev-owy**: Vite HMR WebSocket hardcoded na `wss://pim.localhost` (WebKit nie rozwiąże) + `401` na zasobie tła (cookie refresh HttpOnly na innym hoście przy obejściu localhost). Oba nieobecne w buildzie prod. Dlatego WebKit jest asertowany **render-only**; pełna weryfikacja console-clean Safari wymaga środowiska z `/etc/hosts` (#2182) albo buildu prod.

### Wnioski

1. **Firefox: zdrowy** — 6 krytycznych widoków render + czysta konsola.
2. **Safari: renderuje się poprawnie** na wszystkich 6; automatyczna bramka konsoli nierzetelna w tym dev-env przez DNS gotcha `pim.localhost` (#2182) — nie stwierdzono błędu renderowania specyficznego dla WebKit.
3. Zrzuty per silnik/widok w `apps/admin/playwright-report-browser-matrix/` (gitignore) do wizualnego diffu.
